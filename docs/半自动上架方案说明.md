# 半自动上架工具 说明与评估

> 用途：向非技术人员说明这套工具是什么、能带来什么、有什么问题，供决策审批使用。
> 阅读时间约 5 分钟。

---

## 一句话说明

**让电脑替你把商品信息填进拼多多/抖店的后台，你只负责选类目、检查、点提交。**

不是全自动，是"帮手"，不是"替身"。

---

## 一、现在的问题

在拼多多或抖店上架一个商品，需要填这些内容：

- 商品标题
- 价格
- 库存数量
- 5–10 张商品图片（一张张上传）
- 商品描述
- 各种参数（材质、颜色、尺寸……）

这些信息**在我们自己的系统里已经有了**，但平台后台不认，只能人工一条条复制粘贴。

**实测：一个商品手动上架约 10–15 分钟，其中 80% 是重复劳动。**

每天上 10 个商品，光上架就要两个多小时。

---

## 二、这个工具怎么做

打个比方：

> 你雇了个助手，他坐在你旁边，看着你打开的店铺后台网页。
> 你说"填这个商品"，他就把标题、价格、库存、图片逐个填进去。
> 填完他不动了，剩下的类目选择、检查、点提交由你来做。

技术上做的事就是：**在真实的浏览器里，模拟人的填写动作**。

- 用的是你平时用的浏览器，你登录的账号，你在操作
- 不是破解、不是绕过、不是伪造请求
- 平台看到的就是正常用户在自己后台上架商品

---

## 三、实际怎么用

```
第一步  打开工具，选中要上架的商品（已经从 1688 采集好了）
第二步  工具自动打开拼多多后台的「发布商品」页面
第三步  你在页面上手动选好商品类目（10 秒）
第四步  点工具上的「自动填写」
第五步  电脑自动填：标题、价格、库存、图片、描述
第六步  你检查一遍，改不对的地方
第七步  点「提交」
```

**每个商品大约 3–5 分钟**，比原来的 10–15 分钟省一半以上。

---

## 四、电脑能填什么、不能填什么

### 能自动填（省事的部分）

| 内容 | 说明 |
| --- | --- |
| 商品标题 | 自动写好 |
| 价格 | 自动换算、自动填 |
| 库存数量 | 自动填 |
| 商品编码 | 自动生成 |
| 商品图片 | **直接从我们电脑里的图片上传，不用另外找图床** |
| 商品描述 | 自动写入 |
| 常见参数 | 材质、颜色、尺寸这类，能对上就填 |

### 需要人工做（电脑做不了）

| 内容 | 为什么做不了 |
| --- | --- |
| **选类目** | 平台类目是一层一层选的，选什么决定了后面要填什么，人工判断更准 |
| 品牌 | 多数类目要品牌授权，没有授权填了也无效 |
| 特殊参数 | 比如保质期、执行标准、3C 认证号，只有人知道 |
| 运费模板、发货地 | 要看店铺配置决定 |
| **点提交** | 故意不让电脑点，避免误发 |

## 五、需要投入多少

| 项目 | 投入 |
| --- | --- |
| 首次开发 | 约 1–2 天 |
| 后续适配更多类目 | 每个类目 0.5–2 小时 |
| 日常使用 | 每个商品人工 1–3 分钟 |
| 长期维护 | **每季度检查一次**，每次约 1–2 小时 |

**不需要额外花钱**，不用买软件、不用付月费、不用做备案。

## 六、有哪些问题（重要，请重点看）

### 1. 平台一改版，工具就可能失效

就像遥控器换了按钮位置，原来的按键顺序就不对了。

拼多多和抖店后台**平均每个季度会有一次改版**，改版后工具可能填不进去，需要重新调整。

更麻烦的是：**有时候工具以为填成功了，其实是空的**，要等提交失败才发现。

### 2. 只能用你这台电脑，别人用不了

因为需要用你电脑上登录的浏览器。**同事没法在自己电脑上用**，也没法做成网页给多人访问。

### 3. 必须有人在旁边看着

不能挂着自动跑。每个商品都要人工选类目、核对、点提交。**省的是手的力气，不是人的在场时间。**

### 4. 只能填一部分，不是全部

估计能自动填 **70% 左右**。剩下的必须人工。

### 5. 不能自动改价、不能同步库存

- 卖出去了，库存不会自动减少，要手动改（有超卖风险）
- 要批量调价，还是得一个个改

### 6. 有轻微的账号风险

虽然是真人操作方式，但电脑填得比人快，如果平台风控升级，理论上可能被识别。正常频率使用风险不大，**但一次连续填几十个商品风险会上升**。

### 7. 做不了"真正的大规模自动化"

如果以后商品量涨到每天上百个，这套东西就不够用了，那时候还是得走官方接口或买现成的工具。

---

## 七、值得做吗

| 你的情况 | 建议 |
| --- | --- |
| 每天上架 5–30 个，自己操作 | **值得做**，能省一半以上时间 |
| 每天上架 100 个以上 | 不建议，规模不够用 |
| 需要同事一起用 | 不建议，只能一个人用 |
| 需要自动改价、同步库存 | 不建议，做不到 |
| 商品类目很分散（服装、食品、3C 都做） | 效果会打折，因为每个类目的参数都不一样 |

## 八、和其他办法比

| 办法 | 好处 | 坏处 |
| --- | --- | --- |
| **半自动工具**（本方案） | 不花钱、不需要审核、能立刻用 | 只能一个人用、平台改版要维护、填不全 |
| 官方接口对接 | 全自动、稳定、能多人用 | 需要平台审核，要软著、域名、演示视频，周期长 |
| Excel 批量导入 | 免费、稳定、平台支持 | 需要找入口、模板要求严、图片要有公网地址 |
| 买现成的铺货软件 | 立刻能用、功能全（含库存、订单） | 每月要付费、数据在别人平台 |

## 九、结论与建议

**一句话：这是一个"省时间但要持续照顾"的工具，不是一劳永逸的方案。**

建议的判断顺序：

1. **先花十分钟找平台自带的"商品搬家 / 批量导入"功能**。
   拼多多和抖店的商品管理里通常都有，能直接粘 1688 链接导入商品。
   **如果找到，就不需要做这个工具了**——平台自带的最稳。

2. **找不到，且每天上架量在 30 个以内** → 做，先做一个最简版（一天工作量），试用一周再决定是否继续完善。

3. **每天超过 100 个，或需要几个人一起用** → 不要做，走官方接口或买现成软件。

## 附：技术实现要点（给开发看，其他人可跳过）

- 用 Playwright 通过 CDP 连接**真实启动的 Chrome**（非自动化启动），保持正常浏览器指纹
- 字段定位按页面**可见标签文字**匹配，不写死 DOM 路径，降低改版影响
- 读写 React/Vue 受控组件必须调用原生 value setter 并派发 `input`/`change`/`blur` 事件，否则数据不会进入表单状态
- 图片通过 `setInputFiles` 上传本地文件，不依赖图床
- 下拉选项读全量后用包含匹配，**匹配不到留空，禁止猜测**
- 提交动作不做自动化，保留人工确认环节
